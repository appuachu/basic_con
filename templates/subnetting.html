🎭 Subnet Masks Explained

A subnet mask tells us which bits are the NETWORK portion and which are the HOST portion

255.255.255.0 /24

11111111.11111111.11111111.00000000
■ 24 network bits ■ 8 host bits (254 hosts)

255.255.240.0 /20

11111111.11111111.11110000.00000000
■ 20 network bits ■ 12 host bits (4094 hosts)

255.255.255.252 /30

11111111.11111111.11111111.11111100
■ 30 network bits ■ 2 host bits (2 hosts)
📌 The transition from 1s to 0s can happen at ANY bit position — not just on octet boundaries! This is what allows flexible subnetting.

🎯 Full Workflow: Discover All Devices + ARP Table

The classic network reconnaissance combo — ping everything, then read the ARP cache

1

Ping every IP in your subnet

Use fping -a -g 192.168.1.0/24 or nmap -sn 192.168.1.0/24 to broadcast-ping all 254 addresses. This forces your computer to ARP-resolve every live host.

2

View the ARP table

Run arp -n — every live device now has an entry mapping its IP to its MAC address. This is your complete LAN inventory.

3

Combine with nmap for full picture

After fping populates ARP, run nmap -sV 192.168.1.0/24 to identify each device's OS and open ports.

🛡️

Defending Against ARP Spoofing

  • ✅ Static ARP entries — sudo arp -s 192.168.1.1 00:1A:2B:3C:4D:5E
  • ✅ Dynamic ARP Inspection (DAI) — on managed switches
  • ✅ arpwatch — monitors and alerts on MAC changes
  • ✅ DHCP Snooping — builds trusted IP-MAC bindings
  • ✅ 802.1X authentication — port-level access control
  • ✅ Encrypted protocols (HTTPS, SSH) — even if MITM'd, traffic is unreadable

🔒 Static ARP — What If Someone Manually Sets an IP?

Learn how static ARP entries change the picture — for better or worse

✅

Legitimate Use

Admin pins critical server IPs to known MACs — prevents spoofing of gateway or DNS.

⚠️

Attacker Use

Attacker adds fake static entry mapping victim IP to attacker MAC, hijacking traffic silently.

🚨

Detection

Run arp -n regularly. Look for two IPs with same MAC or static entries you didn't add.

💡 Demo scenario: Attacker at 192.168.1.99 runs sudo arp -s 192.168.1.100 FE:DC:BA:98:76:54 where FE:DC:BA:98:76:54 is the attacker's own MAC. Now any traffic destined for 192.168.1.100 goes to the attacker instead — silently!
